# Color Fidelity Pattern Loss Fix - Bugfix Design

## Overview

用户上传带有明显图案和颜色的衣服图（如卡通图案、彩色星星、印花、刺绣等）进行虚拟试衣时，最终生成的结果图中原始衣服的图案和颜色完全丢失，变成了纯色或灰色衣服。

**关键发现**：调试日志显示 `warped_layer` 的 RGB 值极低（R=14.39, G=13.84, B=13.04, A=14.88），意味着经过 warp 变形后的衣服图层几乎是黑色的，而不是显示原始的彩色图案。问题不在背景去除步骤（`02_input_garment.jpg` 仍然包含正确的图案），而是在 warp/缩放/颜色转移过程中。

**修复策略**：
1. 诊断 `cutout_garment_rgba` → 缩放 → TPS warp → 粘贴流程中的颜色丢失点
2. 确保 RGBA 图层在整个流程中保持原始颜色信息
3. 验证 alpha 通道处理不会意外清除 RGB 通道
4. 确保缩放和 warp 操作使用正确的插值方法保留颜色

## Glossary

- **Bug_Condition (C)**: 当用户上传带有明显图案/颜色的衣服图时，`warped_layer` 的 RGB 值变得极低（接近黑色），导致图案和颜色丢失
- **Property (P)**: `warped_layer` 应该保留原始衣服图的完整颜色和图案信息（RGB 均值应接近原始图的均值）
- **Preservation**: 纯色衣服、无图案衣服、其他试衣模式的行为必须保持不变
- **catvton_color_fidelity_spatial**: `backend/app/services/tryon_v2/warp_engine.py` 中的函数（第 2042 行），负责将原始衣服图案 warp 到 CatVTON 结果中的人物身体位置
- **cutout_garment_rgba**: `backend/app/services/tryon_v2/garment_struct.py` 中的函数（第 342 行），从商品图中提取衣服为 RGBA 格式
- **warped_layer**: 经过缩放、TPS 变形和粘贴后的 RGBA 图层，应该包含原始衣服的颜色和图案
- **original_garment_image**: 在 `backend/app/api/tryon_v2.py` 中保存的原始衣服图，用于颜色保真函数

## Bug Details

### Bug Condition

当用户上传带有明显图案和颜色的衣服图进行虚拟试衣时，`catvton_color_fidelity_spatial` 函数生成的 `warped_layer` RGB 值极低（R=14.39, G=13.84, B=13.04），导致最终结果图中图案和颜色完全丢失。

**Formal Specification:**
```
FUNCTION isBugCondition(input)
  INPUT: input of type {garment_image: Image, garment_category: str, mode: str}
  OUTPUT: boolean

  RETURN hasPatternOrMultipleColors(input.garment_image)
         AND input.mode IN ["detail_fidelity", "blend"]
         AND warped_layer_rgb_mean < 20.0  // 几乎是黑色
         AND original_garment_rgb_mean > 100.0  // 原始图有正常颜色
END FUNCTION
```

**关键观察**：
- `02_input_garment.jpg`（背景去除后的白底图）仍然包含正确的图案和颜色
- 问题发生在 `catvton_color_fidelity_spatial` 函数内部的 warp/缩放/粘贴流程中
- `warped_layer` 的 RGB 均值极低（~14），而 alpha 均值也很低（~15），表明整个图层几乎是透明黑色

## Expected Behavior

### Preservation Requirements

**Unchanged Behaviors:**
- 纯色衣服（无图案）的虚拟试衣必须继续正常工作
- 使用 `mode` 不是 `"detail_fidelity"` 或 `"blend"` 的虚拟试衣请求必须继续按原有逻辑处理
- `_maybe_auto_preprocess` 函数的背景去除和标准化功能必须继续正常工作
- 褶皱和阴影效果（realism pass）必须继续正常工作
- 面部和手部保护功能必须继续正常工作
- 第二件衣服（`garment_image_2`）的处理必须继续正常工作

**Scope:**
所有不涉及带图案/多色衣服的虚拟试衣请求应该完全不受此修复影响。这包括：
- 纯色衣服的虚拟试衣
- 使用其他试衣模式（非 `detail_fidelity` 或 `blend`）的请求
- 背景去除和标准化流程
- 面部/手部保护功能

## Hypothesized Root Cause

基于调试日志和代码分析，最可能的问题是：

1. **Alpha 通道处理错误导致 RGB 通道被清除**：
   - `cutout_garment_rgba` 提取衣服时，可能在某些情况下生成了错误的 alpha 通道
   - 当 alpha 值很低时，后续的缩放/warp 操作可能会将 RGB 值也降低到接近 0
   - 特别是 `_fill_alpha_holes` 函数可能在填充 alpha 孔洞时意外影响了 RGB 通道

2. **缩放操作使用了错误的插值方法**：
   - `gar_scaled = gar_src.resize((s_w, s_h), Image.Resampling.LANCZOS)` 使用 LANCZOS 插值
   - 对于 RGBA 图像，LANCZOS 可能在 alpha 边缘产生预乘 alpha 效果，导致 RGB 值被错误地降低
   - 应该使用 `Image.Resampling.BICUBIC` 或在缩放前分离 RGB 和 alpha 通道

3. **TPS Warp 输出丢失颜色信息**：
   - `TPSWarpEngine.warp()` 接收 RGB 图像，但可能在变形过程中丢失颜色信息
   - 变形后的图像被转换回 RGBA 时，RGB 通道可能已经被破坏
   - 需要检查 TPS warp 的输出是否保留了原始颜色

4. **粘贴操作使用了错误的 alpha 混合模式**：
   - `warped_layer.paste(gar_fitted, (paste_x, paste_y), gar_fitted)` 使用 `gar_fitted` 作为 mask
   - 如果 `gar_fitted` 的 alpha 通道值很低，粘贴操作可能会产生几乎透明的结果
   - 需要确保粘贴前 alpha 通道值正确

5. **羽化操作过度降低了 alpha 值**：
   - `_feather_alpha(warped_layer, radius_px=feather_px)` 可能过度降低了边缘的 alpha 值
   - 如果羽化半径过大或算法有问题，可能导致整个图层的 alpha 值都很低

## Correctness Properties

Property 1: Bug Condition - Warped Layer Preserves Color Information

_For any_ garment image with patterns or multiple colors (pattern_score > 0.3 OR color_variance > 30), the warped_layer generated by catvton_color_fidelity_spatial SHALL preserve the original RGB values such that the mean RGB values of warped_layer (in non-transparent regions where alpha > 128) are within 20% of the mean RGB values of the original garment image.

**Validates: Requirements 2.1, 2.2, 2.3, 2.4**

Property 2: Preservation - Solid Color Garments Unchanged

_For any_ garment image that is solid color (pattern_score <= 0.3 AND color_variance <= 30), the fixed code SHALL produce exactly the same result as the original code, preserving all existing functionality for solid-color garments.

**Validates: Requirements 3.1, 3.2, 3.3, 3.4, 3.5, 3.6**

## Fix Implementation

### Changes Required

假设我们的根本原因分析是正确的，需要进行以下修改：

**File**: `backend/app/services/tryon_v2/warp_engine.py`

**Function**: `catvton_color_fidelity_spatial` (Line 2042)

**Specific Changes**:

1. **修复缩放操作的 alpha 预乘问题**：
   - 在缩放 RGBA 图像前，分离 RGB 和 alpha 通道
   - 分别缩放 RGB 和 alpha 通道
   - 缩放后重新合并，避免 LANCZOS 插值导致的预乘 alpha 效果
   ```python
   # 分离通道
   r, g, b, a = gar_src.split()
   # 分别缩放
   r_scaled = r.resize((s_w, s_h), Image.Resampling.LANCZOS)
   g_scaled = g.resize((s_w, s_h), Image.Resampling.LANCZOS)
   b_scaled = b.resize((s_w, s_h), Image.Resampling.LANCZOS)
   a_scaled = a.resize((s_w, s_h), Image.Resampling.LANCZOS)
   # 重新合并
   gar_scaled = Image.merge("RGBA", (r_scaled, g_scaled, b_scaled, a_scaled))
   ```

2. **确保 TPS Warp 保留颜色信息**：
   - 在 TPS warp 前后添加调试日志，检查 RGB 均值变化
   - 如果 TPS warp 导致颜色丢失，考虑跳过 TPS warp 或使用不同的变形方法
   - 或者在 TPS warp 后，用原始颜色重新填充变形后的区域

3. **修复 alpha 通道处理**：
   - 在 `cutout_garment_rgba` 中，确保 `_fill_alpha_holes` 不会意外影响 RGB 通道
   - 在粘贴前，确保 `gar_fitted` 的 alpha 通道值足够高（至少 > 200 在衣服区域）
   - 添加调试日志检查每个步骤后的 alpha 均值

4. **调整羽化参数**：
   - 减小羽化半径，避免过度降低 alpha 值
   - 或者只在边缘区域应用羽化，保持中心区域的 alpha 值不变

5. **添加颜色保真验证**：
   - 在生成 `warped_layer` 后，检查 RGB 均值是否合理
   - 如果 RGB 均值 < 20，记录警告并尝试使用原始图像重新生成
   - 添加详细的调试日志，记录每个步骤的 RGB 和 alpha 统计信息

**File**: `backend/app/services/tryon_v2/garment_struct.py`

**Function**: `cutout_garment_rgba` (Line 342)

**Specific Changes**:

1. **验证 alpha 孔洞填充不影响 RGB**：
   - 在 `_fill_alpha_holes` 中，确保只修改 alpha 通道，不触碰 RGB 通道
   - 添加断言检查 RGB 通道在填充前后保持不变

2. **添加颜色保真检查**：
   - 在返回 `GarmentCutout` 前，检查 RGBA 图像的 RGB 均值是否合理
   - 如果 RGB 均值异常低，记录警告并返回原始 RGB 图像（不进行 cutout）

## Testing Strategy

### Validation Approach

测试策略遵循两阶段方法：首先，在未修复的代码上运行探索性测试，观察 bug 的具体表现和根本原因；然后，验证修复后的代码正确保留颜色信息并保持现有行为不变。

### Exploratory Bug Condition Checking

**Goal**: 在实施修复之前，在未修复的代码上运行测试，观察 `warped_layer` 的 RGB 值变化，确认或反驳根本原因假设。如果反驳，需要重新假设。

**Test Plan**: 编写测试，在 `catvton_color_fidelity_spatial` 函数的关键步骤（cutout、缩放、TPS warp、粘贴、羽化）后插入断点或日志，记录 RGB 和 alpha 统计信息。在未修复的代码上运行这些测试，观察哪个步骤导致 RGB 值骤降。

**Test Cases**:
1. **Cutout Step Test**: 在 `cutout_garment_rgba` 返回后，检查 RGBA 图像的 RGB 均值（在未修复代码上将失败，如果 cutout 导致颜色丢失）
2. **Scaling Step Test**: 在 `gar_src.resize()` 后，检查 `gar_scaled` 的 RGB 均值（在未修复代码上将失败，如果缩放导致颜色丢失）
3. **TPS Warp Step Test**: 在 TPS warp 后，检查变形后图像的 RGB 均值（在未修复代码上将失败，如果 TPS warp 导致颜色丢失）
4. **Paste Step Test**: 在 `warped_layer.paste()` 后，检查 `warped_layer` 的 RGB 均值（在未修复代码上将失败，如果粘贴导致颜色丢失）
5. **Feather Step Test**: 在 `_feather_alpha()` 后，检查 `warped_layer` 的 RGB 和 alpha 均值（在未修复代码上将失败，如果羽化导致颜色丢失）

**Expected Counterexamples**:
- `warped_layer` 的 RGB 均值 < 20（几乎是黑色）
- 可能的原因：缩放时的预乘 alpha 效果、TPS warp 丢失颜色、alpha 通道值过低导致粘贴失败

### Fix Checking

**Goal**: 验证对于所有带图案/多色的衣服图，修复后的函数生成的 `warped_layer` 保留了原始颜色信息。

**Pseudocode:**
```
FOR ALL input WHERE isBugCondition(input) DO
  warped_layer := catvton_color_fidelity_spatial_fixed(input)
  original_rgb_mean := calculate_rgb_mean(input.garment_image, alpha_threshold=128)
  warped_rgb_mean := calculate_rgb_mean(warped_layer, alpha_threshold=128)

  ASSERT warped_rgb_mean > 20.0  // 不是黑色
  ASSERT abs(warped_rgb_mean - original_rgb_mean) / original_rgb_mean < 0.20  // 在 20% 范围内
END FOR
```

**Test Cases**:
1. **Colorful Pattern Test**: 使用带有彩色图案的衣服图，验证 `warped_layer` RGB 均值接近原始图
2. **Cartoon Pattern Test**: 使用带有卡通图案的衣服图，验证 `warped_layer` RGB 均值接近原始图
3. **Embroidery Pattern Test**: 使用带有刺绣的衣服图，验证 `warped_layer` RGB 均值接近原始图
4. **Multi-Color Test**: 使用带有多种颜色的衣服图，验证 `warped_layer` 保留所有颜色

### Preservation Checking

**Goal**: 验证对于所有不满足 bug 条件的输入（纯色衣服、其他模式），修复后的函数产生与原始函数完全相同的结果。

**Pseudocode:**
```
FOR ALL input WHERE NOT isBugCondition(input) DO
  result_original := catvton_color_fidelity_spatial_original(input)
  result_fixed := catvton_color_fidelity_spatial_fixed(input)

  ASSERT images_are_identical(result_original, result_fixed)
END FOR
```

**Testing Approach**: 属性测试（Property-based testing）强烈推荐用于保留检查，因为：
- 它自动生成大量测试用例覆盖输入域
- 它能捕获手动单元测试可能遗漏的边缘情况
- 它提供强有力的保证：对于所有非 bug 输入，行为保持不变

**Test Plan**: 首先在未修复的代码上观察纯色衣服和其他模式的行为，然后编写属性测试捕获该行为，验证修复后继续工作。

**Test Cases**:
1. **Solid Color Preservation**: 观察未修复代码对纯色衣服的处理，然后验证修复后产生相同结果
2. **Other Mode Preservation**: 观察未修复代码对非 `detail_fidelity`/`blend` 模式的处理，然后验证修复后产生相同结果
3. **Face Protection Preservation**: 观察未修复代码的面部保护功能，然后验证修复后继续工作
4. **Hand Protection Preservation**: 观察未修复代码的手部保护功能，然后验证修复后继续工作
5. **Realism Pass Preservation**: 观察未修复代码的褶皱和阴影效果，然后验证修复后继续工作
