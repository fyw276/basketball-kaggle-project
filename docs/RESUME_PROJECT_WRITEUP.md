# 简历与答辩项目表述

## 1. 推荐项目名称

AI 衣服穿搭决策助手 / Smart Outfit Purchase Decision Assistant

## 2. 一句话定位

基于服饰图像识别、向量相似度检索和用户画像评分的购买决策系统，帮助用户判断一件衣服是否重复、是否适合、是否值得购买。

## 3. 简历项目描述

可直接使用的版本：

> 基于 FastAPI + Flutter 构建 AI 衣服穿搭决策助手，使用 CLIP/FashionCLIP 对服饰图片进行品类、颜色、风格识别与图像特征向量提取，并基于余弦相似度实现衣橱相似单品检索和重复购买预警；结合用户画像、场景、预算、风格偏好等维度设计适合度评分模型，输出可解释的购买决策建议。项目支持衣橱管理、相似度分析、智能推荐、虚拟试衣和 Agent 工具调用流程，当前已整理 20 条购买推荐评测样本，后续计划扩展至 50-100 条用于统计识别准确率、重复购买判断准确率和平均响应耗时。

填入真实指标后的最终版本：

> 基于 FastAPI + Flutter 构建 AI 衣服穿搭决策助手，使用 CLIP/FashionCLIP 对服饰图片进行品类、颜色、风格识别与图像特征向量提取，并基于余弦相似度实现衣橱相似单品检索和重复购买预警；结合用户画像、场景、预算、风格偏好等维度设计适合度评分模型，输出可解释的购买决策建议。在 N 张服饰图片测试集中品类识别准确率达到 X%，在 N 组衣服对中重复购买判断准确率达到 Y%，单次购买决策平均耗时约 Z 秒。

## 4. 背景-动作-结果版本

| 部分 | 内容 |
|---|---|
| 背景 | 用户购买衣服时容易重复购买相似单品，且搭配和适合度判断依赖主观经验 |
| 动作 | 构建图像识别、向量相似度、用户画像评分和购买推荐闭环 |
| 结果 | 将“是否值得买”的主观判断转化为可解释的识别结果、相似度证据和多维评分 |

答辩表达：

> 我没有把项目定位成普通穿搭推荐，而是聚焦在购买决策。系统先看懂衣服，再和已有衣橱比较是否重复，最后结合用户画像判断适不适合、值不值得买。这样项目的价值就从“生成推荐”变成了“降低重复购买和决策成本”。

## 5. 技能点与量化效果

| 技能点 | 项目体现 | 量化效果写法 |
|---|---|---|
| Python / FastAPI | 设计识别、衣橱、相似度、推荐、Agent 等接口 | 支持 N 个核心 API，端到端平均响应耗时 X 秒 |
| CLIP/FashionCLIP 图像理解 | 提取服饰品类、颜色、风格和图像向量 | 在 N 张图片中品类识别准确率达到 X% |
| 向量相似度检索 | 基于余弦相似度检索衣橱相似单品 | Top-N 相似召回率 X%，重复购买判断准确率 X% |
| 用户画像推荐模型 | 结合体型、肤色、风格偏好、预算、场景做适合度评分 | N 条购买样本中推荐结论合理率 X% |
| Agent / RAG / 工具调用 | 通过 Agent 调用衣橱、天气、推荐、记忆等工具 | 支持 N 类工具调用，完成多轮购买咨询流程 |
| 工程化与部署 | 健康检查、统一响应、测试、文档、部署脚本 | 测试用例 N 条，核心流程可本地和部署环境演示 |

## 6. 面试讲解顺序

1. 先讲业务问题：买衣服时重复购买、搭配犹豫、适合度判断主观。
2. 再讲技术闭环：图像识别 -> 向量检索 -> 用户画像评分 -> 购买建议。
3. 讲一个例子：上传一件蓝色衬衫，系统识别后发现衣橱已有高相似衬衫，因此给出谨慎购买。
4. 讲指标：准确率、耗时、支持类别、测试样本数。
5. 最后讲扩展：虚拟试衣和 Agent 是增强体验，不影响主流程闭环。

## 7. 不建议的写法

不要这样写：

> 实现了衣橱管理、虚拟试衣、智能推荐、情绪穿搭、天气穿搭、Agent 对话等功能。

问题是像功能堆砌，看不出技术难点和业务结果。

建议这样写：

> 使用 CLIP/FashionCLIP 提取服饰图像向量，基于余弦相似度实现衣橱相似单品检索和重复购买预警，并结合用户画像构建可解释购买评分模型。
